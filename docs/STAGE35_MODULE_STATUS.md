## چه چیزی در مرحلهٔ ۳۵ عوض شد؟

- صفحهٔ اصلی ۱۸ کارت عملیاتی با لینک‌های معتبر دارد و دیگر پیشرفت ۱۸ ماژول را با برچسب‌های ناقص نسخهٔ قدیمی نشان نمی‌دهد.
- `/factory-release-readiness.html` با API فقط‌خواندنی `/api/v1/factory-release-readiness` تعداد پیش‌نیازهای موجود در SQL آزمایشی را نشان می‌دهد: کالا، مراکز، مسیر مصوب، BOM مصوب، شیفت، MPS مصوب، کنترل پلن مصوب و دو فهرست دلایل فعال.
- هیچ رکوردی، حتی پر شدن همهٔ ۹ پیش‌نیاز، به عنوان **قبولی UAT یا مجوز انتشار** تفسیر نمی‌شود.
- واحد اندازه‌گیریِ کالا و واحد مشخصهٔ کنترل پلن از `UnitOfMeasure` مدیریت می‌شوند؛ کد پایدار، عنوان فارسی و وضعیت فعال دارند. تاریخچهٔ نسخه‌های قبلی بازنویسی نمی‌شود.
- Migration افزایشیِ `20261027210000_StageThirtyFiveUnitsOfMeasure` ۲۵ واحد اولیهٔ قابل مدیریت را اضافه می‌کند. این Migration فقط روی SQL آزمایشی مستقل اعمال شود.
- راهنمای عملی راه‌اندازی نخستین نسخه با Git/Visual Studio/.NET10/User Secrets/SQL مستقل در `docs/FIRST_RUN_VISUAL_STUDIO.md` است.

## ترتیب نهایی‌سازی پیشنهادی

گیت‌های کارخانه در دو جریان دنبال شوند: **اجرای تولید/کیفیت (۸ تا ۱۵)** با سناریوی واقعی نمونهٔ کمک‌فنر و **برنامه‌ریزی/تحلیل (۱ تا ۷ و ۱۶ تا ۱۸)** با نسخه‌های BOM/Routing/MPS و مفروضات تأییدشده. به دلیل عدم اجرای برنامه توسط کاربران کارخانه، گام بعدی تعیین‌کننده اجرای Visual Studio، تست حساب‌ها، ورود اطلاعات آزمایشی و ثبت اشکالات واقعی است؛ موفقیت CI به تنهایی اجازه تغییر وضعیت «تأیید نشده» را نمی‌دهد.

**محدوده قطعی:** هیچ ماژول یا اتصال به انبار، خرید، فروش یا منابع انسانی ایجاد نمی‌شود.
