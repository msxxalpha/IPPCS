# Stage 36 — آزمون عملی هشت ماژول محاسباتی IPPCS

**وضعیت:** قابلیت نرم‌افزاری کدنویسی‌شده برای اجرای آزمایشی؛ پذیرش نهایی کارخانه همچنان **باز**.  
**گیت‌های تحت پوشش:** ۰۲، ۰۳، ۰۵، ۰۶، ۰۷، ۱۴، ۱۶، ۱۷.  
**محیط:** VS / .NET 10 / SQL Server آزمایشی مستقل. هیچ داده‌ای از انبار، خرید، فروش یا منابع انسانی خوانده یا نوشته نمی‌شود.

## نقطهٔ شروع و معنی برچسب‌ها

در Visual Studio پس از اجرای `docs/FIRST_RUN_VISUAL_STUDIO.md`، ابتدا `/factory-release-readiness.html` و سپس `/factory-analytical-verification.html` را باز کنید. صفحه دوم تعداد رکوردهای مرجع و شواهد لازم برای محاسبه را از SQL واقعی IPPCS (نه دادهٔ ثابت/Mock) می‌خواند.

- **MissingInputs:** یک پیش‌نیاز ورود اطلاعات یا محاسبه موجود نیست؛ عدد صفر یا مدرک خیالی تولید نشود.
- **ReadyForFirstTest:** حداقل پیش‌نیاز وجود دارد، اما نتیجهٔ ذخیره‌شده برای این ماژول یافت نشده است.
- **EvidenceAvailable:** یک یا چند Snapshot/رخداد مرتبط موجود است؛ **هیچ نتیجه‌ای به‌عنوان تأیید کیفیت یا مجوز راه‌اندازی تلقی نمی‌شود**.
- **CanRun:** فقط وجود حداقل اطلاعات برای شروع آزمون را نشان می‌دهد؛ کیفیت داده، صحت فرمول، تقویم واقعی کارخانه یا کالیبراسیون ابزار را ضمانت نمی‌کند.
- **مسیر آزمون:** از هر کارت، «اجرای آزمون/نمایش نتیجه» (سرویس واقعی سامانه) یا «ورود به فرم اصلی ماژول» قابل انتخاب است. لینک دوم تب مربوطه را نیز فعال می‌کند.

## جدول آزمون‌ها و خروجی‌های مورد انتظار

**تأکید محاسبات:** روال‌های Backtest، CRP، OEE، هزینه تبدیل و What-if خروجی تحلیلی هستند؛ در صورت نبود اطلاعات معتبر نباید هیچ عددی را به‌عنوان «واقعی و قطعی» گزارش کنند. نرخ‌های تبدیل داخلی IPPCS معادل سند حسابداری نیستند. What-if با درخواست POST اجرا می‌شود، ولی طبق پیاده‌سازی موجود صرفاً محاسبه می‌کند و داده‌ای ذخیره نمی‌کند.

## حالت‌های منفی الزامی

۱. روی پایگاه SQL خالی، همهٔ هشت گیت باید `MissingInputs` باشند.  
۲. حذف/نبود سند نرخ منجمد نباید به «هزینه واقعی تأییدشده» تبدیل شود؛ اختلال ساعت واقعی نیز نباید OEE قطعی تولید کند.  
۳. با MPS پیش‌نویس، برنامه‌ریزی What-if باید رد شود؛ CRP و APS نیز باید محدودیت‌های نسخه/مسیر/شیفت را مستقل بررسی کنند.  
۴. بازه تاریخ شمسی نامعتبر و افق/ضریب ظرفیت غیرمجاز باید خطا بدهند.  
۵. نتیجه ذخیره‌شدهٔ قدیمی باید قابل ردیابی باشد اما با نسخهٔ جدید اشتباه گرفته نشود.  
۶. اجرای What-if نباید تعداد داده‌های Snapshot/SOP/APS/MRP را تغییر دهد.  
۷. نقش فاقد دسترسی Planner نباید بتواند API دارای مجوز برنامه‌ریزی را فراخوانی کند.  
۸. صفحهٔ تشخیصی فقط خواندنی است و حتی اگر هشت گیت «آماده آزمایش» باشند، `releaseAuthorized=false` و `factoryAccepted=0` را حفظ می‌کند.

## نتیجه و محدوده انتشار

نتیجهٔ آزمون‌های خودکار GitHub در `.github/workflows/build.yml` به دو Job `build` و `sqlserver-schema` محدود می‌شود؛ Runner از SQL Server موقت استفاده می‌کند و تست کاربران، ماشین‌های واقعی یا IIS نیست. نسخه تا امضای UAT و بازبینی امنیت و بکاپ همچنان Draft است. برنچ `main` تغییر نمی‌کند.
