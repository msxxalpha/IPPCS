# Stage 40 — آماده‌سازی شواهد SPC و نمونه‌برداری کیفیت

**شاخه توسعه:** `feature/production-platform-foundation` — Draft PR #1. **بدون Migration** و **بدون تغییر در مدل/سوابق تولید**.

## آنچه واقعاً به نرم‌افزار اضافه شد

سرویس `GET /api/v1/manufacturing-orders/{orderId}/spc/{requirementId}/evidence` فقط برای کاربران مجاز، گزارش تحلیلی خواندنی از نتایج اندازه‌گیری غیرقابل بازنویسی موجود ایجاد می‌کند؛ به صفحه `control-plan.html` در تب SPC متصل است.

- شمارش نمونه‌های واقعی، روزهای دارای ثبت (به وقت تهران)، تشخیص زمان ثبت تکراری، مقایسه دوباره وضعیت تاریخی قبول/مردود با حدود مشخصات منجمد دستور و تشخیص نبود حد مشخصات فنی.
- حداقل **۲۵ داده ثبت‌شده** تنها برای آغاز بازبینی آماری اولیه؛ آن را حداقل معتبر برای تمام فرایندها یا طرح رسمی نمونه‌برداری اعلام نمی‌کند.
- محاسبه غربالگری نمودار افراد / دامنه متحرک و علائم اولیه: بیرون از حدود تخمینی سه‌سیگما (با ۲٫۶۶ × میانگین دامنه متحرک)، **۸ نقطه پیاپی در یک سوی میانگین** و **۶ نقطه با روند یک‌جهته سخت‌گیرانه**. علامت‌ها از داده همان دستور و مشخصه محاسبه می‌شوند؛ بدون فرض استقلال و توزیع مناسب داده‌ها.
- فقدان پراکندگی (دامنه متحرک صفر)، ناسازگاری سابقه ثبت و توالی یک‌زمانی موجب عدم ارائه «حد مقدماتی قابل بازبینی» می‌شوند؛ مقدار اندازه‌گیری ناموجود صفر تلقی نمی‌شود.
- تفکیک **حد مشخصات مهندسی** از **حدود کنترل آماری تخمینی**. وجود ۲۵ داده، نبود علامت یا وجود حد تخمینی، به‌تنهایی نشان‌دهنده پایداری، قابلیت فرایند یا گذر از کنترل کیفیت نیست.
- فیلدهای `measurementSystemVerified=false` و `capabilityApproved=false` صریح باقی می‌مانند: هیچ سند کالیبراسیون، Gage R&R/MSA یا طرح نمونه‌برداری مصوب هنوز در این ماژول به‌طور معتبر ثبت و تأیید نمی‌شود.
- API بیش از ۵۰۰ نتیجه را بدون «برش خاموش داده» خطا می‌دهد تا نمودار ناقص مبنای تصمیم نشود.

## مرزها و محدودیت‌ها

**این ویژگی صرفاً تشخیص مقدماتی است، نه اجرای کامل SPC استاندارد یا انجام واقعی MSA.** برای اعلام رسمی نیاز به ثبت و تصویب نسخه‌دار طرح نمونه‌برداری، دوره پایش، فراوانی نمونه، ابزار/دستگاه اندازه‌گیری، کالیبراسیون و مطالعه Gage R&R، معیارهای پایداری، حدود کنترل مصوب، سطح دسترسی و واکنش اصلاحی به علائم وجود دارد. هیچ عدد Cp/Cpk بدون این پیش‌نیازها گزارش نشده است. تغییر خودکار وضعیت دستور، قرنطینه یا تأیید EOL از این سرویس صادر نمی‌شود.

## آزمون

- xUnit برای تاریخچه کوتاه، ۸ نقطه یک‌سو، ۶ نقطه روند، دامنه صفر، ناسازگاری قبول/مردود تاریخی، حد مشخصات ناموجود، تاریخ محلی تهران.
- آزمون UI برای برچسب‌های صریح فقدان MSA، جدول نشانه‌ها، عدم HTML ناامن و خواندنی‌بودن سرویس.
- SQL smoke در سناریوی کنترل نهایی: نتیجه آزمایش واقعی دستور بعد از ثبت به گزارش evidence می‌رسد، اما با یک نمونه هیچ ادعای capability یا MSA صادر نمی‌کند.
- CI همچنان Build، تست .NET، تست‌های مرورگر، تطابق EF Migration و SQL Server موقت را اجرا می‌کند.

## ادامه کار از این نقطه

۱. ثبت طرح نمونه‌برداری نسخه‌دار و حداقل فراوانی آن برای عملیات/مشخصه/مرحله، همراه با کنترل نمونه در گیت کیفیت پس از تأیید روش کارخانه.
۲. رکورد مرجع دستگاه اندازه‌گیری و وضعیت کالیبراسیون، مطالعه MSA/Gage R&R معتبر با قاعده تأیید مستقل کیفیت، بدون ایجاد ماژول انبار/HR.
۳. تعریف حد کنترل مصوب در فاز پایدار و تصمیم واکنش به سیگنال: اعلام هشدار/قرنطینه با حفظ تاریخچه، نه استفاده خودکار از حد تخمینی.
۴. سپس تقویم محدودیت ابزار و تعویض ابزار در APS و گزارش‌های مدیریتی Pareto کیفیت/OEE.

**پذیرش کارخانه:** برای همه ۱۸ ماژول همچنان باز است و بدون شواهد UAT و آزمون فیزیکی مجوز استقرار صادر نمی‌شود.
